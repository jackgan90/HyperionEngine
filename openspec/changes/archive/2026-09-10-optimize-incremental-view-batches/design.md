## Context

基线提交为 `97b2244`，调查证据位于 `out/visibility-investigation-20260910/Analysis.md`。当前场景只有少量可见成员改变，但 collection、局部内容证明、plan structure 和 retained pass 以整个视图为边界。单项 record 缓存已经有效，GPU 时间及实例上传量很小，主要问题是 CPU 重复遍历与结构重建。

所有新增状态由 Renderer 持有，在 Render/RHI 既有线程域内访问。遵循当前 AGENTS.md 的布尔 b 前缀；OpenSpec config 中历史命名描述不覆盖当前仓库规则。

## Goals / Non-Goals

**Goals:**

- 精确维持每视图可见项、顺序与失败覆盖；成员未变时复用有序存储，变化时保留未变项的准备。
- 内置策略对符合条件的静态项增量维护兼容组及稳定批次，首/中/尾变化只影响相关块。
- 批次级提交准备独立复用；当前视图共享参数与源项回执仍正确更新。
- 缓存有容量和退役规则，旧帧及异步 GPU 工作保持原值；提供对应诊断和实测收益证据。

**Non-Goals:**

- 不引入 GPU-driven culling、全局 GPU instance indirection、新后端或第三方依赖。
- 不减少阴影更新频率、阴影质量或 Debug 验证；不修改透明渲染顺序的契约。
- 不执行 Git commit；完成后保留 active change 和可审阅工作区。

## Decisions

### 精确的成员比较先于快照物化

在已准备空间索引和已发布静态 collection 上直接计算当前可见项身份及顺序。相同场景/资源发布且成员完全相同，可以转移或复制安全的旧快照存储，跳过再次收集参数容器和排序；成员不同则只物化/恢复当前项。透明深度排序、未就绪或自定义动态 collection 进入现有完整路径。公开 Collect 的既有行为保持不变，新增准备入口复用同一裁剪判断。

为准备过的项保留视图无关裁剪信息。可证明完全位于视锥内部的保守 world bounds 允许跳过局部矩阵视锥构造；边界项继续使用原有精细判断。先避免重复物化，再依据复测决定进一步层次裁剪的范围；直接冻结裁剪矩阵不能保证正确可见性，不作为实现。

### 持久兼容组与稳定局部块

在内置策略、稳定局部证明、受支持且允许重排的输入上维护每视图规划历史。身份使用完整 scene/slot/generation/local-id，反向索引定位已有成员及块。相同成员和局部证明只刷新当前索引映射；新增、删除或局部变化才触发兼容描述和受影响块的数据更新。按当前共享参数验证组内兼容，不能仅比较 hash 或只看局部 instance 数据。

每个块独立持有不可变内容身份和成员，增删在本块内紧凑化，新增项优先使用兼容组的非满块。块身份不依赖首成员；未变块的实例数据和提交证明保持相同。支持范围之外的策略、顺序障碍、身份冲突、容量/缓存不足或准备失败原子回退到完整规划。首次入组及回退继续复用现有 Describe/Evaluate/CanCombine 契约。

规划缓存只保留有界元数据及非拥有源证明，避免新结构延长资源租约；旧 FRenderBatchPlan 不随新帧修改。实例 block 仍使用现有跨视图 record/byte 缓存，完整数据组装仅发生在受影响块。

独立审计修复后，持久组仅保留 `FRenderBatchStructure`（布局、shader keys、资源 identity）及 capacity，不保留 candidate、compiled program 或参数值树。每次构建从当前项形成临时完整 signature，组比较与新增项准入完成后释放；停用视图的弱源证明与结构元数据仍受原有条目上限约束，旧图依靠自身的 snapshot/packet 拥有关系保持有效。

### 按共享组刷新材料，按批次保留提交准备

对发布版本与成员未变的视图保留共享绑定组及成员索引，按组求值和刷新成员引用，避免逐项查找共享契约和重复状态分支。任何契约、资源依赖或输入可用性改变使该快捷路径退回完整材料准备。保留既有材料输入/参数类型，不引入可被旧帧观察到的可变共享参数对象。

给批次发布独立局部内容证明，RHI 可在视图成员改变后继续认可未变批次的源验证，刷新当前共享常量和 instances 绑定。每个源仍有当前帧回执；错误以原有分组失败/修复事务处理，局部缓存不得绕过 foreign/unready/resource-publication 检查。Native command ownership 和 fence 机制保持不变。

### 有界维护与可解释的计数

检查每帧重复扫描的规划/材料缓存，优先合并相同家族/发布下的维护并使用有界索引或清理游标。源移除与显式失效继续及时解除旧规划的拥有关系；查用仍验证弱引用和完整身份。记录 maintenance 时间及缓存高水位，必要的 GPU 完成检查始终执行。

诊断区分成员变化量、成员列表复用、增量规划更新、实际准备的输入、受影响/复用块和批次提交证明复用；计数不把“读取已有数据”伪装成“无需遍历”。现有计数语义保留，新增列追加到 CSV。 `CapacitySplits` 发布当前保留布局中每个有效兼容组除首块以外的非空块数量，包含仍保留的容量边界；成员退出导致空块时相应减少，静态复用延续该布局计数。

## Risks / Trade-offs

- 历史顺序与块内紧凑化可能改变不可重排项的结果 → 仅在既有策略明确允许重排时启用，排序/障碍场景以负向测试验证完整回退。
- 相机变化下共享数据可能改变兼容关系 → 每次组级更新验证共享值/资源契约，差异触发重分组或完整回退。
- 快照 COW、source generation 复用或 foreign previous 可能产生悬空索引 → 完整发布 key、弱 owner、独立旧帧回归以及异常前原子发布。
- 稳定块可能增加碎片和 draw 数 → 非满块复用、有界容量并记录 draw/块数量；真实场景 A/B 校验图像及覆盖，报告额外提交成本。
- 有预算的维护可能延迟释放 → 缓存硬上限和查用校验持续生效，显式失效/关闭完整清理，GPU 资源仍由既有 fence 决定退役。
- Debug 微基准收益不等于完整帧收益 → Debug/Release 静止、小幅和大幅运动分别交错比较冻结基线，保留 P95、失败、回退与退化数据。

## Migration Plan

先冻结基线并增加机制回归，再依次落地 collection、增量批次、材料/提交准备和维护。使用现有完整路径作为运行时回退和测试对照。完成相关完整构建/测试、风格、命名、边界和 strict OpenSpec 校验后记录证据；不归档、不提交。
